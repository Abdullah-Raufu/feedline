# Feedline

A React single-page app with a Flask API. The React project is the root of this folder;
the Python server only serves the API and the built React files.

```text
Feedline/
├─ index.html          React entry HTML
├─ vite.config.js      Vite build config
├─ package.json        React scripts and dependencies
├─ src/                React source (components, styles, api helpers)
├─ dist/               Built React app (generated by npm run build)
├─ server/
│  ├─ feedline.py      Flask API + RSS/image workers
│  ├─ feedline.db          SQLite database
│  ├─ .news_secret     Flask session secret
│  └─ SMTP_SETUP.md    Email setup for password recovery
└─ start.bat           Builds React and starts the server
```

## Run it

Double-click `start.bat`, or run these commands in this folder:

```bat
npm install
npm run build
npm run server
```

Then open <http://127.0.0.1:5000>.

## Develop the React app

```bat
npm run dev
```

Vite serves the React app on <http://127.0.0.1:5173>. API calls need the Flask server
running too; the app expects the API at `127.0.0.1:5000`.

## Email recovery

Set `NEWS_SMTP_HOST`, `NEWS_SMTP_PORT`, `NEWS_SMTP_USER`, `NEWS_SMTP_PASSWORD` and
`NEWS_SMTP_FROM` before starting the server, as described in `server/SMTP_SETUP.md`.

## Deploy to Vercel

`app.py` is the Vercel WSGI entrypoint. `vercel.json` builds the React app and routes
all requests through Flask so the SPA bootstrap, API, and image proxy keep working.

Set these Vercel environment variables:

- `NEWS_SECRET` — a long random value; keeps sessions stable across cold starts.
- `NEWS_SMTP_*` — optional, for password recovery email.

Vercel functions have a read-only filesystem except `/tmp`, so `NEWS_DB` defaults to
`/tmp/feedline.db` on Vercel. That database is ephemeral. For persistent accounts,
saved stories, and news history, connect an external database and set `NEWS_DB` to it.
The long-running refresh loops only start with `npm run server`; use a scheduled job
or external worker to refresh news on Vercel.
